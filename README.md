# dsh-skins

Wallpaper and theme skins for **DeepSeek Harness** (dsh): a right-sidebar panel
that applies a wallpaper or video to the shell, a token layer that keeps the UI
readable on top of it, and a toolkit that turns a measured image into a complete
skin.

> Community project, unofficial. Not affiliated with or endorsed by DeepSeek.

![A generated demo skin](skins/demo/img_demo-ember_6b1f2c3d/assets/wallpaper.png)

## What you get

- **Backgrounds panel** in the right sidebar: library grid with lazy thumbnails,
  one-click apply, search and tag filters, favourites, drag-to-reorder.
- **Tokens, not a stylesheet**: a skin ships `{light,dark}` pairs for the
  `--dsw-*` custom properties the shell already reads, so components keep their
  contrast and the wallpaper shows through translucent surfaces.
- **Tweaks per skin**: blur, opacity, veil, grayscale/saturation/contrast,
  posterize (a real discrete transfer), subtle parallax.
- **Video themes**: play/pause, mute, speed, and an audio-driven pulse, only on
  video skins.
- **Automation**: follow the system scheme, switch by time range, bind per
  workspace, or rotate on an interval — with a single priority order.
- **Focus mode**: hide the shell and keep the artwork; the Windows titlebar strip
  is cleared and the window goes fullscreen so only the wallpaper remains.
- **Library management**: import/export `.zip` packs, cleanup with a recycle
  bin, batch select, crash-safe atomic writes.
- **No dsh files are modified**. The plugin is a profile patch row plus the files
  it writes into its own data directory.

## Install

**Bundle (recommended)**: install `@henryabbott-13/dsh-skins-bundle` from
**Settings → Plugins**, restart dsh, open the right sidebar → **Backgrounds**.

**Manual**: add one row to your profile's `cordis.patch.yml`:

```yaml
- insert:
    - id: ui-dsh-skins
      name: '@henryabbott-13/dsh-plugin-skins'
```

Full options (including `dataDir`, `defaultSkin`, development checkouts) are in
[docs/install.md](docs/install.md).

## Skins are user content

No artwork ships here. `skins/demo/` contains three **procedurally generated**
skins (the image above is one of their wallpapers) purely as format examples:
copy them into `<dataDir>/output/skins/` to see the panel work, then build your
own from media you have the rights to.

```bash
node tools/make-demo-skins.mjs          # regenerate the demos
dsh-skins check skins/demo              # validate a library
```

The skin format — ids, `skin.json`, `tokens.json`, scoped CSS, asset fallbacks —
is specified in [docs/skin-format.md](docs/skin-format.md).

## Compatibility

Built against dsh **0.2.1** (Electron desktop). The theme/token layer uses the
documented `overrideTokens` contract; the chrome and focus-mode fixes target
hashed shell class names and match them by **suffix**, which is what keeps them
working across the 0.2.0 → 0.2.1 rename. Details, the rule, and how to read the
built-in diagnostics: [docs/compat.md](docs/compat.md).

## Repository layout

```
packages/
  plugin/     host half (routes, catalog, uploads, packs) + browser half (panel)
  bundle/     npm bundle: a patch layer that installs the plugin by name
  toolkit/    deriveDesign / buildTokens / themeCss + the dsh-skins CLI
skins/demo/   three generated skins (no third-party art)
tools/        bundle/manifest checks, PNG writer, demo generator
tests/        10 sandboxed suites (831 checks), toolkit and host-config contracts
docs/         install, skin format, compatibility
```

## Develop

```bash
node packages/plugin/build.mjs     # build the client bundle
node tests/run.mjs                 # 10 suites against a sandbox (no dsh install)
node tests/toolkit.mjs             # toolkit contract
node tests/host-config.mjs         # dataDir / default skin / pipeline contract
node tools/verify-bundle.mjs       # one registration, id matches the package name
```

CI runs the same commands on Node 20. The suites stub the shell, and every image
in this repository is generated by code, so a clean checkout tests and builds
with no artwork and no dsh.
